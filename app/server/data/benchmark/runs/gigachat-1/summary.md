# Прогон gigachat-1: GigaChat-2-Max

Срез из 30 статей и 15 вопросов, модель `GigaChat-2-Max` (GigaChat API, Freemium-режим), параметры генерации по умолчанию у провайдера. Параметры и контрольные суммы — [config.json](config.json), выдача, ответы и ручная оценка — [results.jsonl](results.jsonl). Прогон выполнен в контейнере `benchmark`, где нет git, поэтому поле `revision` в `config.json` пустое; код этого прогона (версия с GigaChat) отдельно не коммитился.

| Метрика | Значение |
| --- | ---: |
| Recall@3 | 0,7333 (22 из 30 релевантных позиций) |
| MRR@3 | 1,0000 |
| Accuracy | 0,0 (0 из 10) |
| Correct Rejection Rate | 0,8 (4 из 5) |

Технических сбоев — 3 (Q05, Q06, Q11); они считаются ошибочными ответами. Метрики поиска совпадают с прогоном [bm25-baseline](../bm25-baseline/summary.md): поиск не менялся.

## Наблюдения

1. **Фильтр GigaChat.** Все три сбоя — ровно те запросы, в контексте которых была УК РФ ст. 63 (отягчающие обстоятельства); ни один из остальных 12 запросов её не содержал. После прогона сервер повторяет отклонённый фильтром запрос без одной из статей и записывает исключённую статью в `diagnostics.filtered_out`.
2. **Отказы при полном контексте** (Q01, Q03, Q07). Этот прогон не различал, отказалась ли модель сама или пояснение отклонила проверка меток (абзац без метки). После прогона причина записывается в `diagnostics` (`model_refusal`, `rejection`) — её покажет следующий прогон.
3. **Поиск** пропускает статьи с другой формой слов (Q04, Q08, Q10): BM25 сравнивает слова буквально. Нормализация словоформ — предложение для поиска.
4. **Формат.** Ответ Q09 содержал разметку Markdown; после прогона сервер её убирает, контракт API требует простой текст.
