# Юридический RAG-ассистент — архитектура

> **Статус: сервер, клиент и запуск через Docker Compose готовы; языковая модель — DeepSeek-V4-Flash через Cloud.ru Foundation Models (раздел 6).** Владелец — Ушаков Леонид (интеграция, бэкенд); поиск по корпусу описывает Грачев Константин в `spec/tech/rag.md`, интерфейс — Корегин Илья в [spec/product/scenarios.md](../product/scenarios.md). Правила изменения — [AGENTS.md](../../AGENTS.md).

## 1. Состав системы

Два постоянно работающих контейнера в одной сети Docker Compose; языковая модель — внешний сервис Cloud.ru Foundation Models с OpenAI-совместимым API (раздел 6):

| Сервис | Папка | Роль | Порт наружу |
|---|---|---|---|
| `nginx` | `app/nginx/` | единственная точка входа: отдаёт статику клиента, проксирует `/api/*` на `server`. Клиент (`app/client/`, React + TypeScript, Vite) собирается в статику на первом этапе образа `nginx`, отдельного контейнера клиента нет | `NGINX_PORT`, по умолчанию 80 |
| `server` | `app/server/` | NestJS + TypeScript: API, корпус, поиск, обращение к LLM | нет (только внутри сети) |

Сервис `benchmark` (профиль `benchmark`) не работает постоянно: его запускают командой `docker compose run` для прогона бенчмарка (раздел 8).

Клиент и сервер видны браузеру как один адрес: запросы к `/api/*` идут через Nginx, поэтому CORS не нужен. В разработке клиент можно запускать отдельно (`vite dev`) с прокси `/api` на сервер.

```text
Браузер ──► nginx:80 ──► /        статика клиента
                  └────► /api/*   ──► server:3000 (main.ts: проверка запроса)
                                           │
                                           ▼
                                      ChatService ──► SearchService (BM25) ──► корпус статей
                                           │
                                           └────────► llm.service ──► Cloud.ru Foundation Models
```

## 2. Пайплайн обработки вопроса

`POST /api/chat` выполняет по порядку:

1. **Проверка входа** в обработчике: длина, число слов, `scope`, `history`.
2. **Поиск** (`SearchService`): по `message` (с учётом `scope`) выбираются статьи с `score ≥ MIN_SCORE`. Алгоритм и параметры — `spec/tech/rag.md`. Затем `ChatService` оставляет только статьи, совпавшие с вопросом хотя бы одним содержательным словом: совпадение лишь по служебным словам («как», «с», «и»; список — `app/server/src/chat/function-words.ts`) есть почти в любой статье и не означает, что статья относится к вопросу. Из оставшихся берутся первые `MAX_CONTEXT_DOCS` по убыванию балла. Метрики поиска бенчмарка (Recall@3, MRR@3) считаются по выдаче `SearchService` и от этого шага не зависят.
3. **Нет статей** → ответ с готовым текстом «Ничего не найдено» (раздел 5 в [scenarios.md](../product/scenarios.md)), `sources = []`; LLM не вызывается. Дисклеймер сервер добавляет и сюда (п. 6), а критерий А2.1 в scenarios.md требует текст без дисклеймера; расхождение согласуют Ушаков и Корегин.
4. **Генерация** (`ChatService` и `llm/llm.service.ts`): модели передаются системный промпт, фрагменты статей как контекст в пределах `LLM_CONTEXT_BYTES`, поместившиеся в этот бюджет последние сообщения `history` и вопрос. Модель обязана ссылаться только на переданные статьи. При `LLM_PROVIDER=stub` вместо пояснения возвращается выдержка из найденного фрагмента. Если встроенный фильтр модели отклонил запрос (`finish_reason: content_filter`), запрос повторяется без одной из статей, по очереди с конца списка, пока фильтр не пропустит; исключённая статья не попадает в `sources`. Отказ фильтра приходит быстро, поэтому повторы почти не добавляют времени.
5. **Проверка ссылок:** метки в ответе сверяются с метками фактически переданного контекста. Метка, в которой узнаются источник и номер статьи из контекста, приводится к виду `[Конституция РФ ст. N]` или `[УК РФ ст. N]`, по которому интерфейс открывает статью: например, `[Конституция РФ, ст. 23]` и `[ст. 23 Конституции РФ, ч. 2]` становятся `[Конституция РФ ст. 23]`. Выделение Markdown (`**`, `__`) и заголовки `#` убираются: контракт требует простой текст. Каждый абзац пояснения должен содержать хотя бы одну такую метку; если в каком-то абзаце метки нет или метка указывает на статью не из контекста, всё пояснение заменяется фразой «В найденных статьях недостаточно сведений для ответа.», а `sources` содержит статьи из контекста. Подробности — `spec/tech/rag.md`, раздел «Ответ API».
6. **Дисклеймер** «Это справочная информация, а не юридическая консультация.» добавляет сервер последним абзацем.
7. **Недоступность LLM** (таймаут, сеть, ошибка провайдера, отказ встроенного фильтра модели) → ответ 200 с текстом «Пояснение недоступно: языковая модель не ответила. Список подходящих статей ниже.», дисклеймером и непустым `sources`.

## 3. Структура `app/server/`

```text
app/server/
├── Dockerfile                # сборка TypeScript и образ для запуска (раздел 8)
├── package.json
├── data/
│   ├── demo/articles.json    # демо-записи DEMO-*
│   └── benchmark/            # срез из 30 статей, вопросы и прогоны (spec/tech/benchmark.md)
├── benchmark/                # скрипты прогона и оценки бенчмарка
├── src/
│   ├── main.ts               # настройки из окружения, проверка запроса, /api/health и /api/chat, журнал, запуск
│   ├── chat/                 # chat.service.ts — пайплайн: поиск → отбор статей → контекст → модель → проверка меток → дисклеймер; function-words.ts — служебные слова
│   ├── corpus/corpus.ts      # загрузка и проверка корпуса
│   ├── search/               # токенизация и BM25 (bm25.ts), нарезка и ранжирование (search.service.ts)
│   └── llm/                  # llm.service.ts — клиент OpenAI-совместимого API; prompts.ts — промпт и метки
└── test/                     # rag.test.cjs — поиск и пайплайн; chat.test.cjs — отбор статей и метки; api.test.cjs — контракт API по HTTP; llm.test.cjs — клиент модели
```

Приложение Nest состоит из одного модуля: контроллер и модуль объявлены в `main.ts` внутри `createApp()`. Запрос проверяет функция `parseRequest` без `class-validator`; при ошибке — 422 со стандартным телом NestJS. `ChatService` получает поиск и функцию вызова модели через конструктор, поэтому тесты подменяют их заглушками, а бенчмарк создаёт то же приложение через `createApp()`.

## 4. Корпус

Статьи Конституции РФ и Уголовного кодекса РФ хранятся файлом в `app/server/data/` и загружаются в память при старте. Запись:

| Поле | Тип | Содержимое |
|---|---|---|
| `id` | строка | идентификатор статьи в корпусе |
| `code` | строка | `constitution` или `criminal_code` |
| `article` | строка | номер статьи как в официальной редакции |
| `title` | строка | заголовок статьи |
| `text` | строка | полный текст статьи |
| `source_url` | строка | адрес официальной редакции |
| `edition_date` | строка | дата редакции (ГГГГ-ММ-ДД) |

Тексты берутся только из официальных редакций, выдуманные нормы запрещены (AGENTS.md, раздел 2). Демо-записи `DEMO-001`, `DEMO-002`, `DEMO-003` лежат отдельно (`data/demo/`) и в реальный корпус не попадают.

Корпус выбирает `CORPUS_MODE`: `demo` — демо-записи из `data/demo/articles.json`; `official` — статьи из `data/articles.json` или из файла `CORPUS_PATH`. Полного корпуса пока нет: для контрольной точки сервер работает на срезе из 30 статей `data/benchmark/articles.json`, так настроен `app/.env.example`. Ошибка в файле корпуса останавливает запуск сервера.

Формат хранения, нарезка длинных статей на фрагменты и выбор поиска (лексический, векторный или гибридный) фиксирует `spec/tech/rag.md`.

## 5. Контракт API

Префикс всех маршрутов — `/api`. Любое изменение — по протоколу AGENTS.md, раздел 4.

### `POST /api/chat`

| Поле запроса | Тип | Правило |
|---|---|---|
| `message` | строка | после обрезки пробелов по краям: 3–1000 символов, не меньше 3 слов; слово — непрерывная последовательность букв или цифр (`[^\W_]+` в Python-нотации, `/[\p{L}\p{N}]+/gu` в JS) |
| `scope` | строка | `all` (по умолчанию), `constitution`, `criminal_code` |
| `history` | массив | до 10 объектов `{ "role": "user" \| "assistant", "content": строка }`, `content` не длиннее 4000 символов |

| Поле ответа | Тип | Содержимое |
|---|---|---|
| `answer` | строка | простой текст без Markdown, абзацы разделены `\n\n`; ссылки на статьи — метки в квадратных скобках; последний абзац — дисклеймер |
| `sources` | массив | использованные статьи по убыванию `score`, при равенстве — по `id` |
| `sources[].id` | строка | идентификатор статьи в корпусе; у демо-записей `DEMO-001` и т. д. |
| `sources[].code` | строка | `constitution` или `criminal_code` |
| `sources[].article` | строка | номер статьи |
| `sources[].title` | строка | заголовок статьи |
| `sources[].text` | строка | полный текст статьи |
| `sources[].source_url` | строка | адрес официальной редакции |
| `sources[].score` | число | оценка релевантности, неотрицательная |

Пример ответа (демонстрационные данные):

```json
{
  "answer": "Демонстрационные данные: ответ составлен по вымышленным записям.\n\n[DEMO-001] Вымышленная статья описывает защиту тайны переписки.\n\nЭто справочная информация, а не юридическая консультация.",
  "sources": [
    {
      "id": "DEMO-001",
      "code": "constitution",
      "article": "DEMO",
      "title": "Тайна переписки (демонстрационная запись)",
      "text": "Демонстрационный текст, не являющийся нормой права.",
      "source_url": "демонстрационные данные",
      "score": 12.47
    }
  ]
}
```

Коды ответов: 200 — успех (в том числе пустой `sources` и недоступная модель); 422 — не прошла проверка полей; 5xx — ошибка сервера. Тело 422 — стандартное для NestJS (`message`, `error`, `statusCode`); интерфейс его не показывает.

### `GET /api/health`

Ответ 200: `{ "status": "ok", "version": "<версия>", "llm": "<провайдер>" }`.

## 6. Языковая модель и переключатель провайдера

**Решение (Ушаков Леонид, 2026-11-21):** модель `deepseek-ai/DeepSeek-V4-Flash` в Cloud.ru Foundation Models, через провайдер `openai_compatible`. Качество ответов проверено прогоном бенчмарка `deepseek-1`: Accuracy = 0,6, Correct Rejection Rate = 1,0, технических сбоев нет ([summary.md](../../app/server/data/benchmark/runs/deepseek-1/summary.md)); по результатам следующих прогонов модель можно сменить переменной `LLM_MODEL` на другую из каталога Foundation Models без изменения кода.

Почему Cloud.ru Foundation Models:

- **Доступ из России без VPN и оплата в рублях.** API OpenAI, Anthropic и Google из России закрыты, OpenRouter в 2026 году прекратил работу с российскими клиентами, собственный API DeepSeek не принимает российские карты.
- **Дёшево.** `DeepSeek-V4-Flash` стоит 43,30 ₽ за 1 млн входных и 86,58 ₽ за 1 млн выходных токенов (тарифы на ноябрь 2026 года). Один прогон бенчмарка — порядка сотни тысяч токенов, то есть несколько рублей.
- **Стандартный API.** Сервис совместим с OpenAI: `POST https://foundation-models.api.cloud.ru/v1/chat/completions`, ключ — `Authorization: Bearer <LLM_API_KEY>`. Специального кода, получения токенов и дополнительных сертификатов не нужно.

Отклонённый вариант — GigaChat API в бесплатном режиме: в прогоне бенчмарка `gigachat-1` его встроенный фильтр отклонил все запросы, в контексте которых была УК РФ ст. 63, а физлицо не может настроить фильтр.

Ограничения: сервис платный — запросы списываются с баланса аккаунта Cloud.ru, которому принадлежит ключ; при нулевом балансе модель не отвечает (сценарий А4). Ключ ограничен сроком действия, заданным при создании. Для доступа нужен именно API-ключ сервисного аккаунта (вкладка «API-ключи»), а не ключ доступа.

`llm/llm.service.ts` вызывает модель через функцию «сообщения → текст», провайдер выбирается переменной `LLM_PROVIDER`:

| Значение | Что делает |
|---|---|
| `stub` | возвращает выдержку из найденного фрагмента без сети; для прототипа, тестов и проверки пайплайна |
| `openai_compatible` | `POST <LLM_BASE_URL>/chat/completions` в формате OpenAI, ключ — `Authorization: Bearer <LLM_API_KEY>`; без ключа заголовок не отправляется (для локального Ollama) |

Работа с моделью:

- **Ошибки провайдера.** Код ответа и сообщение провайдера (до 300 символов) попадают в предупреждение «Модель не ответила: …»; пользователь видит сценарий А4.
- **Фильтр модели.** Ответ, остановленный встроенным фильтром (`finish_reason: content_filter`), повторяется без одной из статей (раздел 2, п. 4). Если фильтр отклоняет все варианты, это отказ провайдера: пользователь видит сценарий А4, в журнале — причина.
- **Проверка меток.** Пояснение, в котором хотя бы один абзац без точной метки вида `[УК РФ ст. N]`, сервер заменяет фразой о недостатке сведений (раздел 2, п. 5). Долю таких замен нужно смотреть в прогоне бенчмарка.

Другие сервисы с OpenAI-совместимым API, в том числе локальный Ollama, подключаются через `openai_compatible` заменой `LLM_BASE_URL`, `LLM_MODEL` и `LLM_API_KEY`.

## 7. Переменные окружения

Для Docker Compose настройки задаются в `app/.env` по образцу `app/.env.example`. `docker-compose.yml` передаёт серверу переменные из таблицы, а незаданную или пустую переменную сервер заменяет значением по умолчанию. При запуске без Docker сервер читает переменные процесса, файл `.env` не читается. Новая переменная добавляется в `app/.env.example`, `app/docker-compose.yml` и эту таблицу в одном коммите.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `NGINX_PORT` | порт Nginx на хосте | `80` |
| `SERVER_PORT` | порт сервера внутри сети; по нему же Nginx проксирует `/api/` | `3000` |
| `LLM_PROVIDER` | `stub` или `openai_compatible`; в `app/.env.example` — `openai_compatible` | `stub` |
| `LLM_BASE_URL` | адрес API провайдера без `/chat/completions`; для `openai_compatible` обязателен | нет; в `app/.env.example` — `https://foundation-models.api.cloud.ru/v1` |
| `LLM_MODEL` | имя модели; для `openai_compatible` обязательно | нет; в `app/.env.example` — `deepseek-ai/DeepSeek-V4-Flash` |
| `LLM_API_KEY` | ключ Bearer; для Cloud.ru — Key Secret API-ключа сервисного аккаунта; только на сервере, не `VITE_*` | — |
| `LLM_TIMEOUT_MS` | таймаут вызова модели; таймаут прокси Nginx на 30 с больше | `30000`, в `app/.env.example` — `60000` |
| `MAX_CONTEXT_DOCS` | сколько статей передавать модели | `5` |
| `MIN_SCORE` | порог релевантности; подбирается на проверочных вопросах | `0` |
| `CORPUS_MODE` | режим загрузки корпуса, `demo` или `official` | `demo` |
| `CORPUS_PATH` | путь к JSON выбранного корпуса; относительный путь отсчитывается от `app/server` | `data/demo/articles.json` или `data/articles.json` по `CORPUS_MODE` |
| `LLM_CONTEXT_BYTES` | бюджет входных сообщений в байтах с запасом под обёртку, подбирается под окно модели | `24000` |

## 8. Docker и Nginx

- `app/docker-compose.yml` описывает постоянные сервисы `server` и `nginx` и сервис `benchmark` (профиль `benchmark`) для прогона бенчмарка командой `docker compose run`. `nginx` запускается, когда сервер готов: compose проверяет `GET /api/health` изнутри контейнера сервера. Команды запуска — в README, раздел «Запуск».
- `server` (`app/server/Dockerfile`, контекст — `app/server/`): первый этап на `node:24-alpine` ставит зависимости и собирает TypeScript, второй содержит только production-зависимости, `dist/`, `data/` (без `data/benchmark/runs/`) и `benchmark/` и работает от пользователя `node`. Compose запускает его с `init: true`, чтобы `docker compose down` останавливал процесс сразу.
- `benchmark` собирается из того же `app/server/Dockerfile`, получает те же переменные окружения, что `server`, и запускает `node <скрипт>` из `app/server/benchmark/`. Папка `app/server/data/benchmark/runs/` подключена с компьютера, поэтому результаты прогонов остаются в репозитории.
- `nginx` (`app/nginx/Dockerfile`, контекст — `app/`): первый этап на `node:24-alpine` собирает клиент (`npm ci` и `npm run build` в `app/client/`), второй — `nginx:stable-alpine` с результатом сборки в `/usr/share/nginx/html`. В контекст сборки попадают только `client/` и `nginx/` (`app/.dockerignore`).
- Конфигурация Nginx — шаблон `app/nginx/default.conf.template`. При запуске контейнера `app/nginx/render-config.sh` подставляет порт сервера из `SERVER_PORT` и таймаут прокси: `LLM_TIMEOUT_MS` в секундах с округлением вверх плюс 30 с (при 60000 мс — 90 с). Так Nginx не обрывает запрос раньше, чем сервер вернёт ответ сценария А4.
- `location = /` — если в адресе нет параметра `mock`, относительное перенаправление на `/?mock=off`: клиент без параметра показывает демонстрационные ответы, а в Docker-сборке чат должен сразу работать с настоящим API. Адреса с любым значением `mock` (`?mock=offline` и др.) не меняются. Когда клиент начнёт по умолчанию обращаться к API, перенаправление можно убрать.
- `location /` — статика с `try_files $uri $uri/ /index.html`, `index.html` не кешируется; `location /assets/` — файлы сборки Vite с хешем в имени, кеш на год; `location /api/` — `proxy_pass` на `server:<SERVER_PORT>` без изменения пути. Адрес `server` определяется встроенным DNS Docker при каждом запросе, поэтому после пересоздания контейнера сервера Nginx перезапускать не нужно.
- Секреты в образы не вшиваются, передаются переменными окружения при запуске (AGENTS.md, раздел 6).

## 9. Логирование и данные пользователей

- Сервер хранит диалоги только в памяти запроса: история приходит от клиента в `history`, на сервере нигде не сохраняется.
- В логи пишутся метаданные (время, код ответа, длительность, число найденных статей), но не текст вопросов и ответов. Сервер при старте пишет режим и путь корпуса, число статей, провайдера, модель и адрес API LLM (без ключа), а если ключ не задан — предупреждение; на каждый `POST /api/chat` — строку JSON `{ "route", "status", "duration_ms", "sources" }`; время добавляет логгер NestJS. Если модель не ответила (сценарий А4), сервер пишет предупреждение «Модель не ответила: …» с причиной: тип ошибки, сетевой код или код ответа провайдера и его сообщение (до 300 символов). Если пояснение заменено фразой о недостатке сведений, журнал различает два случая: «Модель ответила, что в найденных статьях недостаточно сведений» и «Пояснение модели отклонено проверкой меток: абзацев: M; без метки: №1, …; меток статей не из контекста: K» — только номера абзацев и счётчики, без текста ответа. Если запрос прошёл фильтр модели только без какой-то статьи, сервер пишет «Фильтр модели отклонил запрос; ответ получен без статьи …» с идентификатором статьи. Бенчмарк записывает эти причины в поле `diagnostics` файла `results.jsonl`. Журнал смотрят командой `docker compose logs server`.
- Cloud.ru Foundation Models получает текущий вопрос, поместившуюся в бюджет историю диалога и выдержки из найденных статей; это указано в README. Ключ хранится только в `app/.env` и переменных окружения сервера.
