# Юридический RAG-ассистент

Чат-бот для вопросов по Конституции РФ и Уголовному кодексу РФ: пользователь задаёт вопрос обычными словами, система находит в текстах нормативных актов подходящие статьи, а языковая модель отвечает на их основе со ссылками на номера статей. Ответ — справочная информация, а не юридическая консультация.

## Статус проекта

Готово:

- документация проекта: описание, правила работы (`AGENTS.md`), история изменений (`CHANGE_HISTORY.md`), пользовательские сценарии (`spec/product/scenarios.md`), архитектура и контракт API (`spec/tech/architecture.md`);
- решения по стеку и структуре репозитория (ниже);
- клиент на React; в Docker-сборке Nginx открывает его сразу в режиме настоящего API (`?mock=off`);
- сервер NestJS с BM25, сборкой контекста, проверкой меток и OpenAI-совместимым провайдером LLM;
- языковая модель: `DeepSeek-V4-Flash` в Cloud.ru Foundation Models (OpenAI-совместимый API, оплата в рублях);
- запуск через Docker Compose: Nginx со статикой клиента и прокси `/api`, сервер, бенчмарк в контейнере;
- спецификация BM25 и RAG, размеченный срез из 30 статей и базовый прогон BM25 (Recall@3, MRR@3);
- прогон бенчмарка `deepseek-1` с моделью `DeepSeek-V4-Flash`: Recall@3 = 0,7333, MRR@3 = 1,0, Accuracy = 0,6, Correct Rejection Rate = 1,0; разбор ошибок — [summary.md](app/server/data/benchmark/runs/deepseek-1/summary.md).

Ещё не сделано:

- поиск с учётом форм слов: из-за буквального сравнения BM25 теряются статьи в Q04 и Q08 бенчмарка;
- полный корпус Конституции РФ и Уголовного кодекса РФ: сейчас сервер работает на срезе из 30 статей;
- реальный API по умолчанию в самом клиенте: при запуске через Vite пока нужен параметр `?mock=off`.

## Как это работает

```text
Браузер ──► Nginx ──► Клиент (React, статика)
               │
               └─ /api ──► Сервер (NestJS) ──► поиск статей по корпусу ──► LLM
                                  │                                          │
                                  └────────── ответ + ссылки на статьи ◄─────┘
```

1. Пользователь вводит вопрос в чате и, при желании, выбирает источник: Конституция, Уголовный кодекс или оба.
2. Сервер ищет в корпусе статьи, близкие к вопросу.
3. Найденные статьи передаются языковой модели как контекст; модель отвечает только на их основе.
4. Интерфейс показывает ответ со ссылками вида `[УК РФ ст. N]` и список использованных статей; по ссылке открывается полный текст статьи.

Принцип RAG: модель не «помнит» законы, а получает нужные статьи вместе с вопросом. Это снижает риск выдуманных норм и позволяет проверить каждый ответ по источнику.

## Запуск

Пошаговая инструкция для нового участника: от установки программ до работающего чата и повторения контрольной проверки. Команды одинаковы для macOS, Linux и Windows, если не сказано иное. На Windows используйте PowerShell или Git Bash.

Языковая модель — `DeepSeek-V4-Flash` в сервисе Cloud.ru Foundation Models. Он работает из России без VPN, оплачивается в рублях и стоит меньше рубля за вопрос; почему выбран он — [architecture.md](spec/tech/architecture.md), раздел 6.

### 1. Установить программы

| Программа | Зачем | Проверка |
|---|---|---|
| Git | получить код | `git --version` |
| Docker Desktop с Compose v2 (на Windows — с WSL 2, на Linux можно Docker Engine) | запуск приложения и бенчмарка | `docker compose version` |
| Node.js 22 или новее | только для разработки без Docker | `node --version` |

### 2. Получить код и создать настройки

```bash
git clone https://github.com/arrgn/juristic-RAG-assistant.git
cd juristic-RAG-assistant
cp app/.env.example app/.env
```

`app/.env` — личные настройки, в git он не попадает. Образец настроен для контрольной точки: корпус — срез из 30 статей, модель — `deepseek-ai/DeepSeek-V4-Flash` в Cloud.ru. Не хватает только ключа (шаг 3).

### 3. Получить API-ключ Cloud.ru

1. Зарегистрируйтесь на cloud.ru и пополните баланс: Foundation Models оплачивается по числу токенов. Для демонстрации и нескольких прогонов бенчмарка хватит нескольких десятков рублей.
2. Создайте сервисный аккаунт и сгенерируйте для него API-ключ — по [инструкции Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__authentication). В разделе «Учетные данные доступа» нужна вкладка **«API-ключи»**: ключ с вкладки «Ключи доступа» модель не примет. При создании выберите сервис Foundation Models и срок действия.
3. Скопируйте **Key Secret** до закрытия окна: потом его не показать. ID ключа приложению не нужен. Вставьте секрет в `app/.env`:

   ```text
   LLM_API_KEY=<Key Secret>
   ```

Ключ — секрет: не записывайте его в код, документы, сообщения коммитов и общие чаты. Все запросы с ключом оплачивает аккаунт, которому он принадлежит. Если ключ мог утечь, удалите его в консоли Cloud.ru и создайте новый.

Подойдёт и другой сервис с OpenAI-совместимым API, например локальный Ollama: задайте в `app/.env` его `LLM_BASE_URL` и `LLM_MODEL`, а `LLM_API_KEY` оставьте пустым.

### 4. Запустить и проверить

Из папки `app/`:

```bash
docker compose up --build -d
```

Первый запуск скачивает образы и собирает клиент и сервер, это занимает несколько минут. Затем:

1. `docker compose ps` — сервисы `server` и `nginx` запущены, у `server` состояние `healthy`.
2. `docker compose logs server` — в начале есть строка «LLM: openai_compatible (deepseek-ai/DeepSeek-V4-Flash, foundation-models.api.cloud.ru)» и нет предупреждения «LLM_API_KEY не задан».
3. http://localhost/api/health — ответ `{"status":"ok","version":"0.1.0","llm":"openai_compatible"}`.
4. http://localhost — Nginx сам добавит `?mock=off`, и чат будет работать с настоящим API. На вопрос «Каков предел задержания до судебного решения?» за 5–30 секунд приходит пояснение со ссылкой вида `[Конституция РФ ст. 22]`; по ссылке открывается текст статьи.

Без ключа приложение можно запустить с `LLM_PROVIDER=stub` в `app/.env`: вместо пояснения придёт выдержка из найденной статьи.

**Вопросы для демонстрации.** Корпус пока содержит 30 статей, поэтому для показа подходят вопросы по их темам. В каждом вопросе ниже нужная статья стоит в поиске первой.

| Вопрос | Ожидаемый результат |
|---|---|
| Какая статья Конституции защищает тайну переписки? | пояснение по `[Конституция РФ ст. 23]` |
| Каков предел задержания до судебного решения? | пояснение по `[Конституция РФ ст. 22]` |
| пример «Необходимая оборона» в интерфейсе | пояснение по `[УК РФ ст. 37]` |
| Какие виды соучастников преступления выделяет закон? | пояснение по `[УК РФ ст. 33]` |
| Кто обязан доказывать виновность обвиняемого? | пояснение по `[Конституция РФ ст. 49]` |
| Какой номер телефона у дежурного адвоката в моём районе? | отказ «В найденных статьях недостаточно сведений для ответа.»: в статье 48 есть право на адвоката, но не телефон |
| пример «Вопрос не по теме» (борщ) | «Ничего не найдено», модель не вызывается |

Ответ модели меняется от запуска к запуску; прогоните вопросы перед показом и проверьте баланс Cloud.ru.

### 6. Если что-то не работает

| Признак | Причина и решение |
|---|---|
| `docker compose up` не может скачать образы | нет доступа к Docker Hub: проверьте сеть; при необходимости настройте зеркало реестра (`registry-mirrors` в Docker Desktop → Settings → Docker Engine) |
| порт 80 занят | задайте `NGINX_PORT=8080` в `app/.env` и откройте http://localhost:8080 |
| `docker compose up` сообщает, что `server` не запустился или `unhealthy` | `docker compose logs server` назовёт причину. «Недопустимое значение LLM_PROVIDER=gigachat» — `app/.env` остался от прежней версии: перенесите строки `LLM_*` из `app/.env.example`. «Проверьте LLM_BASE_URL» или «Задайте LLM_MODEL» — пустое или неверное значение в `app/.env` |
| в чате записи `DEMO-*` | не создан `app/.env`, либо в адресе задан другой режим `mock` (например, `?mock=on`): откройте http://localhost без параметров |
| «Пояснение недоступно: языковая модель не ответила» | причину пишет журнал сервера строкой «Модель не ответила: …», расшифровка — в таблице ниже |
| на вопрос по теме корпуса приходит «В найденных статьях недостаточно сведений для ответа.» | журнал сервера называет причину. «Модель ответила, что в найденных статьях недостаточно сведений» — так решила сама модель: часто нужная статья не попала в первые пять из-за другой формы слов, переформулируйте вопрос словами из статьи. «Пояснение модели отклонено проверкой меток: …» — в ответе был абзац без метки статьи (журнал называет его номер) или метка статьи не из контекста ([architecture.md](spec/tech/architecture.md), раздел 2, п. 5). Отметьте такие вопросы в разборе ошибок |

| В строке «Модель не ответила: …» | Что сделать |
|---|---|
| `LLM HTTP 401`, например «Invalid API key secret» | в `LLM_API_KEY` не Key Secret API-ключа: ключ с вкладки «Ключи доступа», ID вместо секрета или секрет скопирован не полностью; либо истёк срок действия ключа. Создайте API-ключ заново (шаг 3) |
| `LLM HTTP 403` | ключ принят, но доступа к модели нет: проверьте, что ключ создан для Foundation Models, и роли сервисного аккаунта в консоли Cloud.ru |
| сообщение о балансе, оплате или квоте | пополните баланс аккаунта Cloud.ru |
| `LLM HTTP 404` | неверное имя модели в `LLM_MODEL` или адрес в `LLM_BASE_URL`: точное имя — на странице модели в каталоге Foundation Models |
| `LLM HTTP 429` | превышен лимит частоты запросов: подождите минуту и повторите |
| `LLM HTTP 413` или сообщение о длине контекста | запрос больше окна модели: уменьшите `LLM_CONTEXT_BYTES` |
| `finish_reason: content_filter` | встроенный фильтр модели отклонил все варианты запроса: сервер уже повторил его без каждой из статей по очереди. Это ограничение модели — отметьте вопрос в разборе ошибок. Если повтор помог, в журнале строка «Фильтр модели отклонил запрос; ответ получен без статьи …» |
| `TimeoutError` | модель не успела ответить: увеличьте `LLM_TIMEOUT_MS` |
| `ECONNREFUSED`, `ENOTFOUND` или `EAI_AGAIN` | нет связи с `foundation-models.api.cloud.ru`: проверьте интернет и прокси, при включённом VPN попробуйте без него |

Корпус пока содержит только 30 статей. Вопросы вне их тем получают слабо связанные статьи: BM25 сравнивает слова буквально.

### 7. Разработка без Docker

Сервер читает настройки из переменных окружения, файл `app/.env` он не читает; без переменных сервер работает на демо-корпусе с заглушкой модели. Из корня репозитория:

```bash
npm --prefix app/server ci
npm --prefix app/server run build
CORPUS_MODE=official CORPUS_PATH=data/benchmark/articles.json \
LLM_PROVIDER=openai_compatible LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1 \
LLM_MODEL=deepseek-ai/DeepSeek-V4-Flash LLM_API_KEY='<Key Secret>' \
npm --prefix app/server start
```

В PowerShell переменные задаются отдельно:

```powershell
$env:CORPUS_MODE="official"; $env:CORPUS_PATH="data/benchmark/articles.json"
$env:LLM_PROVIDER="openai_compatible"; $env:LLM_BASE_URL="https://foundation-models.api.cloud.ru/v1"
$env:LLM_MODEL="deepseek-ai/DeepSeek-V4-Flash"; $env:LLM_API_KEY="<Key Secret>"
npm --prefix app/server start
```

Клиент запускается во втором терминале:

```bash
cd app/client
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://localhost:5173), с параметром `?mock=off`: Vite передаёт запросы `/api` серверу на `localhost:3000`. Параметр `?mock=offline` воспроизводит недоступность сервиса.

### 9. Повторить контрольную проверку

Бенчмарк запускается в контейнере `benchmark` с теми же настройками модели, что у сервера в `app/.env`; Node.js на компьютере не нужен. Результаты сохраняются в `app/server/data/benchmark/runs/<имя прогона>/`; в репозитории уже есть прогоны `bm25-baseline`, `gigachat-1` и `deepseek-1`. Порядок и правила оценки — [benchmark.md](spec/tech/benchmark.md). Команды — из папки `app/`.

**Проверка сохранённых результатов — без ключа Cloud.ru и без оплаты:**

- метрики поиска: прогон с заглушкой вместо модели даёт Recall@3 = 0,7333 и MRR@3 = 1,0, как в отчётах (имя прогона — любое новое):

  ```bash
  docker compose run --rm -e LLM_PROVIDER=stub benchmark benchmark/run.cjs bm25-check
  ```

- Accuracy и Correct Rejection Rate по сохранённой ручной оценке прогона `deepseek-1` — 0,6 и 1,0:

  ```bash
  docker compose run --rm benchmark benchmark/score.cjs deepseek-1
  ```

**Новый прогон с моделью:**

1. Прогон: 15 вопросов, несколько минут, несколько рублей с баланса Cloud.ru.

   ```bash
   docker compose build benchmark
   docker compose run --rm benchmark benchmark/run.cjs deepseek-2
   ```

   Первая команда пересобирает образ бенчмарка после изменений в коде. Имя прогона — латиница, цифры, `-` и `_`; папки с таким именем ещё не должно быть, иначе прогон остановится с ошибкой `EEXIST`. Если в итоге `degraded` больше 0, часть ответов не получена: причины — в строках «Модель не ответила: …» выше в выводе. Для разбора ошибок в каждой строке `results.jsonl` есть поле `diagnostics`: `llm_error` — сбой модели, `model_refusal` — модель сама ответила, что сведений недостаточно, `rejection` — пояснение отклонено проверкой меток, `filtered_out` — статьи, без которых запрос прошёл фильтр модели.

2. Оцените ответы вручную. В `results.jsonl` прогона каждая строка — один вопрос: сравните `answer` с `expected_answer` того же вопроса в `app/server/data/benchmark/questions.json` и замените `"review":{"correct":null,"reason":null}` на `"review":{"correct":true,"reason":"…"}` или `false` с причиной. Строки с `"degraded":true` не заполняются и считаются ошибкой.

3. Посчитайте Accuracy и Correct Rejection Rate:

   ```bash
   docker compose run --rm benchmark benchmark/score.cjs deepseek-2
   ```

4. Запишите четыре метрики и разбор ошибок в `summary.md` прогона по образцу `runs/bm25-baseline/summary.md`.
