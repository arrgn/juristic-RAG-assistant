# Юридический RAG-ассистент

Чат-бот для вопросов по Конституции РФ и Уголовному кодексу РФ: пользователь задаёт вопрос обычными словами, система находит в текстах нормативных актов подходящие статьи, а языковая модель отвечает на их основе со ссылками на номера статей. Ответ — справочная информация, а не юридическая консультация.

## Как это работает

```text
Браузер ──► Nginx ──► Клиент (React, статика)
               │
               └─ /api ──► Сервер (NestJS) ──► поиск статей по корпусу ──► LLM
                                  │                                          │
                                  └────────── ответ + ссылки на статьи ◄─────┘
```

1. Пользователь вводит вопрос в чате и, при желании, выбирает источник: Конституция, Уголовный кодекс или оба.
2. Сервер ищет в корпусе статьи, близкие к вопросу.
3. Найденные статьи передаются языковой модели как контекст; модель отвечает только на их основе.
4. Интерфейс показывает ответ со ссылками вида `[УК РФ ст. N]` и список использованных статей; по ссылке открывается полный текст статьи.

Принцип RAG: модель не «помнит» законы, а получает нужные статьи вместе с вопросом. Это снижает риск выдуманных норм и позволяет проверить каждый ответ по источнику.

## Структура репозитория

Весь код и Docker-файлы лежат в `app/`.

```text
juristic-RAG-assistant/
├── README.md               # описание проекта (этот файл)
├── AGENTS.md               # правила для участников и ИИ-агентов
├── CLAUDE.md               # одна строка @AGENTS.md: правила для Claude Code
├── CHANGE_HISTORY.md       # история изменений
├── LICENSE
├── spec/
│   ├── product/
│   │   └── scenarios.md    # пользовательские сценарии и строки интерфейса
│   └── tech/
│       ├── architecture.md # архитектура, контракт API, LLM, Docker
│       └── rag.md          # корпус и поиск (появится при реализации поиска)
└── app/
    ├── docker-compose.yml  # запуск всех сервисов (появится вместе с кодом)
    ├── .env.example        # образец настроек; сам .env в git не попадает
    ├── client/             # React + TypeScript, Dockerfile клиента
    ├── server/             # NestJS + TypeScript, Dockerfile сервера, корпус и поиск
    └── nginx/              # nginx.conf, Dockerfile прокси
```

## Запуск

Кода пока нет: раздел заполняется, когда появится `app/docker-compose.yml`. Планируемый способ запуска из папки `app/`:

```bash
cp .env.example .env
docker compose up --build
```

После запуска приложение открывается через Nginx на http://localhost (порт будет указан в `app/.env.example`).
