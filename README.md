# Юридический RAG-ассистент

Чат-бот для вопросов по Конституции РФ и Уголовному кодексу РФ: пользователь задаёт вопрос обычными словами, система находит в текстах нормативных актов подходящие статьи, а языковая модель отвечает на их основе со ссылками на номера статей. Ответ — справочная информация, а не юридическая консультация.

## Статус проекта

Готово:

- документация проекта: описание, правила работы (`AGENTS.md`), история изменений (`CHANGE_HISTORY.md`), пользовательские сценарии (`spec/product/scenarios.md`), архитектура и контракт API (`spec/tech/architecture.md`);
- решения по стеку и структуре репозитория (ниже);
- клиентский макет на React с демонстрационными ответами;
- сервер NestJS с BM25, сборкой контекста и OpenAI-совместимым провайдером;
- спецификация BM25 и RAG, размеченный срез из 30 статей и базовый прогон BM25.

Ещё не сделано:

- Nginx и конфигурация Docker Compose;
- корпус: тексты Конституции РФ и Уголовного кодекса РФ не загружены;
- оценка качества генерации на размеченном корпусе.

## Как это работает

```text
Браузер ──► Nginx ──► Клиент (React, статика)
               │
               └─ /api ──► Сервер (NestJS) ──► поиск статей по корпусу ──► LLM
                                  │                                          │
                                  └────────── ответ + ссылки на статьи ◄─────┘
```

1. Пользователь вводит вопрос в чате и, при желании, выбирает источник: Конституция, Уголовный кодекс или оба.
2. Сервер ищет в корпусе статьи, близкие к вопросу.
3. Найденные статьи передаются языковой модели как контекст; модель отвечает только на их основе.
4. Интерфейс показывает ответ со ссылками вида `[УК РФ ст. N]` и список использованных статей; по ссылке открывается полный текст статьи.

Принцип RAG: модель не «помнит» законы, а получает нужные статьи вместе с вопросом. Это снижает риск выдуманных норм и позволяет проверить каждый ответ по источнику.

## Запуск

### Текущий клиентский макет

Из корня репозитория выполните команды ниже и откройте адрес, который выведет Vite.

```bash
cd app/client
npm ci
npm run dev
```

Макет показывает демонстрационные ответы. Параметр `?mock=offline` воспроизводит недоступность сервиса. Параметр `?mock=off` подключает `POST /api/chat`, когда сервер доступен.

### Сервер BM25 и RAG

Из корня проекта в отдельном терминале выполните:

```bash
npm --prefix app/server ci
npm --prefix app/server run build
npm --prefix app/server start
```

Откройте Vite с параметром `?mock=off`. По умолчанию сервер использует
отдельный демонстрационный корпус и локальную заглушку, которая показывает
фрагменты источников.

Для работы с официальными статьями подготовьте корпус в формате
[спецификации](spec/tech/rag.md), положите его в `app/server/data/articles.json`
и задайте `CORPUS_MODE=official`. Путь можно задать через `CORPUS_PATH`.
Для генерации задайте `LLM_PROVIDER=openai_compatible`, `LLM_BASE_URL`
с префиксом API (например, `http://localhost:11434/v1`), `LLM_MODEL`
и при необходимости `LLM_API_KEY`. При внешнем провайдере ему передаются
вопрос, история и выдержки из статей.

### Запуск через Docker после добавления Compose

После добавления Compose и официального корпуса задайте параметры провайдера LLM в `app/.env` по [спецификации архитектуры](spec/tech/architecture.md). Запустите сервисы из корня репозитория.

```bash
cd app
cp -n .env.example .env
# Заполните настройки провайдера в .env перед запуском.
docker compose up --build
```

Откройте адрес Nginx с `?mock=off` и задайте вопрос по корпусу. Команды ниже проверяют доступность сервера и один запрос при стандартном порте.

```bash
curl -fsS http://localhost/api/health
curl -fsS http://localhost/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Какие гарантии предусмотрены при задержании?","scope":"all","history":[]}'
```

Порядок подготовки среза корпуса и повторения контрольной проверки описан в [бенчмарке](spec/tech/benchmark.md).
